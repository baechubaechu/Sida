# 웹 화면 (webui/app)

`python webapp.py`(Windows는 `run.bat`)로 서버를 켜면 열리는 첫 화면(`http://127.0.0.1:8765/`)입니다. 팀원이 Figma 초안으로 만든 목업(PR #39)을 서버의 JSON API에 연결했습니다. 화면은 순수 HTML/CSS/JS이고 빌드 과정이 없습니다. 프로젝트와 대화는 브라우저가 아니라 이 PC의 `projects/` 폴더에 저장됩니다.

예전 서버 렌더링 화면(`/classic` 허브와 `/p/<프로젝트>` 페이지)은 2026-10-23에 없앴습니다. 서버가 템플릿(`webui/templates`, `webui/static`)으로 그리는 화면은 ChatGPT 로그인 결과 페이지 하나만 남았습니다.

## 화면과 API

| 화면 | 쓰는 API |
|---|---|
| 프로젝트 목록 (`#/`) | `GET /api/projects`(정렬과 끌어서 정한 순서 `list` 포함, 바꾸면 `PUT /api/projects/list`, 프로젝트 폴더의 `.project_list.json`), 카드의 대지(주소·용도지역·필지 윤곽, 맨 위 "이어서 하기"의 대지면적·법정 건폐율·용적률)는 프로젝트마다 `GET /api/projects/{name}/site`, 예시 프로젝트 `POST /api/projects/sample`, 삭제 `DELETE /api/projects/{name}`(카드의 "삭제" → 확인 창, 실행 중인 작업이 있으면 409) |
| 새 프로젝트 (`#/new`, 목록 위에 뜨는 창) | `POST /api/projects` (`name`, `fields.type`·`site`·`intention`) |
| Conductor 대화 (`#/project/<이름>`, 왼쪽 대화 패널과 아래 명령창) | `GET .../session`(대화 목록 `talks`), 첫 인사 `POST .../session/opening`, 새 대화 `POST .../talks`, 대화 `GET .../talks/{id}`, 메시지 `POST .../talks/{id}/messages`, 진행 `GET .../session/jobs/{id}` |
| 전문가 페이지 (`#/project/<이름>/expert/<id>` 결과, `.../chat/<채팅 id>` 분석 채팅, `.../versions/<버전 id>` 이전 버전) | 결과 문서 `GET .../modules/{agent}`, 이전 버전 `GET .../modules/{agent}/versions`, `.../versions/{id}`, 실행·수정 요청 `POST .../session/experts/{agent}/run`, 분석 채팅 목록과 새 채팅 `GET`/`POST .../experts/{agent}/chats`, 채팅 `GET .../experts/{agent}/chats/{chat_id}`, 메시지 `POST .../chats/{chat_id}/messages`, 평가 `POST .../experts/{agent}/feedback` |
| 대지 페이지 (`#/project/<이름>/site` 대지 사실, `.../site/ordinance` 조례, `.../site/uses` 계획 용도, `.../site/find` 찾기) | 대지 사실 `GET .../site`, 조례 `GET .../site/ordinance`와 조문 선택 `PUT .../site/ordinance/options/{id}`, 용도 이름 찾기 `GET /api/site/uses`, 계획 용도 조회·지우기 `POST`/`DELETE .../site/uses...`, 지역 목록 `GET /api/site/regions`, 지번으로 찾기 `GET /api/site/lots`, 주소로 찾기 `POST .../site/parcels`, 조회해 저장 `PUT .../site`, 지도 `GET /api/site/map`·`GET /api/site/parcel-at`·`GET /api/site/shapes`, 브리프의 대지 주소 `GET /api/projects/{name}` |
| 설계 상태 반영 승인 | `POST .../state-proposals/{id}/apply`, `.../skip` |
| 설정 창 | `GET`/`PUT /api/settings`, 키 `PUT /api/settings/keys/{openrouter·vworld·vworld_domain·data_go_kr·law·relay_url·relay_token}`, ChatGPT 로그인 `/api/settings/chatgpt...` |

| 제도판 | `GET .../board`(종이·AI 섹션·대지 도면·매스안 수치), 종이 `POST`/`PATCH`/`DELETE .../board/papers...`, AI 섹션 `POST .../board/tray/{id}/place`, `DELETE .../board/tray/{id}`. 아이디어 보드 `POST .../board/ideas`, `PATCH`/`DELETE .../board/ideas/{id}`, `PUT .../board/ideas/order`, 종이 넣기 `POST .../board/ideas/stow`, 꺼내기 `POST .../board/ideas/{id}/place`. 캐드·라이노 내보내기 `GET .../board/export?format=dxf|3dm&active=<매스안 id>`(제도판 머리의 "내보내기" 버튼과 명령 `export`). 자세한 것은 [board-api.md](board-api.md) |

## 동작

- Conductor의 대화 머리 또는 "이전 대화" 목록의 ⋯ 메뉴를 열고 "대화 삭제"를 선택한 뒤 확인하면 대화와 메시지를 삭제합니다. 한 번에 한 메뉴만 열리고, 바깥 클릭·Esc로 닫습니다. `DELETE /api/projects/{name}/talks/{id}`를 사용합니다. 첫 대화도 삭제할 수 있고 새로고침해도 되살아나지 않으며, 지운 번호는 재사용하지 않습니다. 실행 중인 작업이 있으면 409로 보호합니다. 브리프·설계 상태·전문가 결과·제도판은 건드리지 않습니다. 삭제 표시(`talks/.deleted/<id>.json`)에는 내용 없이 빈 배열만 남깁니다.

- 보류 중인 전문가(`tier: held`: 개념 정리자·공간 검토자·시스템 자문가)는 전문가 목록, 실행 명령의 보기와 전문가 연결 링크에서 숨깁니다. 목록과 프로젝트 진행 수는 현재 개발하는 7명만 셉니다. 설정·프롬프트·기존 결과와 대화 기록은 유지하며, 다시 `core`로 바꾸면 UI에 나타납니다.

- 프로젝트 목록의 "정보 수정" 또는 제도판 머리의 프로젝트 이름(✎)을 누르면 이름·유형·설명(설계 의도)을 고칩니다. `GET/PATCH /api/projects/{name}/info`를 사용하며, 브리프의 해당 절만 바꾸고 다른 절과 자료는 유지합니다. 화면 이름(`display_name`)은 `Project Name` 절에 저장하고 기존 프로젝트 주소·폴더 id(`name`)는 유지합니다. 실행 중이거나 읽은 뒤 문서가 바뀌면 409로 저장을 거절합니다. 대지 주소·필지는 대지 화면에서 따로 고릅니다.
- 제도판 오른쪽 아래 축척은 현재 확대율을 CSS 픽셀(96dpi) 기준으로 표시합니다. 가까운 표준 축척으로 반올림하지 않습니다. 숫자를 누르고 `500` 또는 `1:500`을 입력하면 그 배율로 맞춥니다. 함께 표시한 거리 막대의 화면 길이는 실제 모델 길이에 대응합니다. 평면은 대지 평면, 3D는 시선 중심을 지나는 화면 평면 기준이며 원근에 따라 앞뒤의 배율은 다릅니다. 화면의 물리적 크기를 알 수 없으므로 모니터 위에 실제 자를 대어 재는 인쇄 축척은 아닙니다.

- 화면 맨 아래에 명령창이 있습니다(2026-11-01 지훈 결정, 실험 기능). 띄어쓰기 없는 영어 한 단어가 명령 목록(`webui/app/command-model.js`의 `COMMANDS`)에 있으면 그 명령을 실행하고, 그 밖의 글은 모두 Conductor에게 갑니다. Enter는 실행, Shift+Enter는 줄 바꿈입니다. 한 단어를 치는 동안 맞는 명령이 떠서 ↑↓로 고르고 Tab으로 채우며, 입력칸 앞 표시가 Enter를 누르면 할 일(명령 이름, "AI에게", 명령이 묻는 "답")을 미리 보여 줍니다. 한글 자판이 켜진 채 친 명령(ㅔㅣ무 → plan)도 영어 글자로 되돌려 읽습니다(한 글자는 제외). 빈 칸에서 Enter는 직전 명령 반복, Esc는 취소, 입력칸 밖에서 Space를 누르거나 글자를 치면 명령창으로 커서가 옮겨 가고, 친 글자도 명령창에 들어갑니다. `help`는 명령 목록을 보여 주고, `run`처럼 고를 것이 있는 명령은 명령창 위에 보기를 띄워 번호나 이름으로 답받습니다. 명령 결과는 명령창 위 기록 세 줄에 남습니다.
- Conductor 대화는 왼쪽 패널에서 읽고 이어서 질문합니다. 명령창의 "대화" 버튼으로 열고 닫으며, 닫으면 제도판이 넓어집니다. 보던 대화·작성 중인 글·선택 자료·읽던 위치는 다시 열 때 유지됩니다. 제도판을 이동하거나 확대해도 패널은 접히지 않습니다. "이전 대화"(또는 `talks` 명령)에서 저장된 대화를 고르고, "＋ 새 대화"로 별도 대화를 시작합니다. 화면을 처음 열면 가장 최근 대화를 보여 줍니다. 새 대화의 첫 메시지를 보내기 전에는 서버에 대화를 만들지 않습니다.
- 하단 명령창에서 보낸 질문도 새 대화를 만들고 왼쪽 패널에서 열립니다. 이어지는 질문은 패널의 입력칸에 씁니다. 대화 기록은 각각 따로이고 브리프·설계 상태·전문가 결과·제도판은 같이 봅니다. 제도판에서 고른 종이는 질문과 함께 그 대화로 가고, 입력칸에서 칩의 ×로 빼거나 "＋ 고른 종이 넣기"로 더합니다.
- 첫 대화(`01`, 예전의 Conductor 대화)가 비어 있으면 화면을 열 때 Conductor가 먼저 인사하고 왼쪽 패널이 열립니다.
- 메시지를 보내면 작업이 끝날 때까지 1초마다 진행을 받아 그립니다. 그동안 보내기 버튼은 꺼집니다(한 프로젝트에 작업 하나).
- Conductor나 설계자가 전문가를 실행하면 화면 오른쪽 아래 알림이 시작, 결과, 검토 필요를 알리고, 대화에 분석 카드가 남습니다. 카드나 전문가 패널을 누르면 그 전문가 화면이 열립니다.
- 프로젝트 화면은 팀원의 제도판 시험판 UI(PR #63, 옮긴 뒤 저장소에서 지움)를 따릅니다. 왼쪽에 Conductor, 가운데 제도판, 오른쪽에 전문가가 회색 바탕 위 카드로 놓이며, 제도판 아래에는 명령창이 있습니다. 양쪽 패널은 각각 접을 수 있습니다. 패널(대화·속성·레이어·전문가)은 라이노처럼 탭을 끌어 다른 묶음에 넣거나, 묶음의 위·아래 3분의 1에 놓아 위아래로 나누거나, 비어 있거나 접힌 쪽의 화면 가장자리에 놓아 반대쪽으로 옮깁니다. 제도판 위에 놓으면 라이노처럼 떠 있는 창이 되어, 머리를 끌어 옮기고 오른쪽 아래 모서리로 크기를 바꾸며, 다른 탭을 넣거나 ⇥로 오른쪽에 다시 붙입니다. 나눈 묶음 사이 선을 끌어(↑↓, 두 번 누르면 반반) 높이를 정합니다. 배치와 너비는 이 PC 서버의 `<projects 폴더>/.panel_layout.json`에 남고(`GET/PUT /api/panel-layout`), `layout` 명령으로 기본 배치(왼쪽 대화, 오른쪽 속성·레이어·전문가)로 돌아갑니다. 대지·전문가 페이지가 열리면 오른쪽 자리를 차지합니다. 900px 이하 화면에서는 배치와 상관없이 아래 탭으로 대화 / 제도판 / 나머지 패널을 하나씩 봅니다. 패널과 제도판 사이 경계를 끌어 양쪽 너비를 각각 조절합니다. 방향키로도 조절하고, 경계를 두 번 누르면 기본 너비로 돌아갑니다. 조절한 비율은 같은 화면에서 패널을 닫았다 열어도 유지하며, 가운데 제도판은 최소 320px을 남깁니다. Conductor 패널은 하단 명령창 옆까지 화면 높이를 채우고 입력창은 그 맨 아래에 붙습니다. 하단 명령창은 패널이 열려 있어도 유지됩니다. 제도판 머리의 "프로젝트"로 목록에, ⚙로 설정에 갑니다(프로젝트 삭제는 목록 화면에서). 각 쪽은 맨 위 묶음의 ‹·›로 접고, 제도판 머리 양끝에 나타나는 그쪽 패널 이름 버튼(오른쪽은 `board` 명령도)으로 다시 펼칩니다. 제도판은 숨기지 않습니다.
- 오른쪽 전문가 패널에는 대지 사실과 전문가 목록이 있습니다. 전문가마다 상태 점(회색 실행 전, 파랑 실행 중, 주황 검토 필요, 초록 완료)과 "실행" 버튼이 있고, 이름을 누르면 "결과 문서 보기", "＋ 새 분석 채팅", 분석 채팅 목록("분석 01 · 첫 질문")이 펼쳐집니다. 펼친 상태는 화면을 다시 그려도 유지됩니다. 고른 종이가 있으면 "실행"에 함께 갑니다. 아래 "검토 진행"에 지금 실행 중인 전문가가 나옵니다.
- 아이디어 보드는 제도판 위 한구석에 늘 떠 있습니다(2026-11-07 지훈 결정, 이전에는 오른쪽 패널의 탭). 평소에는 아이디어마다 동그라미 하나(글은 번호, 메모 ✎, 매스안 ▣, 사진은 작은 사진)만 한 줄로 보이고, 마우스를 올리면 펼쳐져 아이디어마다 내용이 조금씩 보입니다. 마우스를 떼면 다시 접히고, 글을 쓰는 중이거나 "고정"을 누르면 펼친 채로 둡니다. 휴대폰처럼 마우스가 없으면 ⌄를 눌러 폅니다. 동그라미 줄의 빈 곳이나 펼친 보드의 머리를 끌면 옮겨지고, 놓으면 가장 가까운 구석에 붙습니다(패널을 여닫아 제도판 크기가 바뀌어도 그 구석에 있음). 펼친 보드는 오른쪽 아래 모서리로 크기를 바꿉니다. 자리·크기·고정은 화면을 새로 열면 처음(오른쪽 위)으로 돌아갑니다. 제도판의 종이를 끌면 종이가 흐려지고 마우스 밑에 동그라미가 생기며, 그 동그라미를 보드에 놓으면 종이가 보드로 들어갑니다(대지 종이는 안 들어감). 보드의 동그라미를 제도판으로 끌어 놓으면 그 자리에 다시 꺼내지고(글만 있던 아이디어는 메모 종이로), 보드 안에서 끌면 순서가 바뀝니다. 펼친 보드에서는 직접 적기(Enter 추가, 고른 종이가 있으면 연결할지 고름), ↑↓ 순서, 고치기(종이는 "한마디"), 잠시 빼기(AI에게 보내지 않음), 제도판에 꺼내기, 고른 종이 연결, 지우기(한 번 더 눌러 확인)가 있습니다. 대화 메시지의 "＋ 아이디어로"를 누르면 그 메시지(드래그로 고른 부분만도)가 들어가고 보드가 잠깐 펼쳐집니다. Conductor 대화에서 넣은 아이디어는 그 대화와 연결됩니다. AI는 아이디어를 읽기만 합니다([board-api.md](board-api.md) "아이디어 보드"). 명령 `idea`는 보드를 펼쳐 고정합니다.
- 전문가를 열면 제도판은 왼쪽에 그대로 있고 오른쪽 반쪽이 그 전문가의 페이지가 됩니다(대지 페이지도 같은 자리). 페이지의 ×나 `board` 명령으로 닫습니다. 휴대폰에서는 아래 대화·제도판·전문가 탭으로 한 화면씩 바꿔 봅니다.
- 전문가 페이지에는 탭 세 개(결과, 분석 채팅, 이전 버전)와 검토 영역(실행·다시 실행, 수정 요청, 평가)이 있습니다. 페이지가 넓으면 검토 영역이 오른쪽 열로, 좁으면 탭 아래 한 줄로 갑니다. 대지 분석가는 채팅 탭이 없고 수정 요청만 있습니다.
- 결과 탭은 전문가마다 다르게 배치합니다. 결과 문서의 `## 제목` 섹션을 잘라 카드, 표, 배지(확실/아마/확인, 브리프/후보/가정 등), 체크리스트, 순서 목록, 접는 문답으로 보여 줍니다. 배치는 `model.js`의 `EXPERT_LAYOUTS` 표 하나에 있어 그 표만 고치면 바뀝니다. 표에 없는 섹션은 끝에 그대로 붙고, 섹션을 하나도 못 찾으면 문서를 그대로 보여 줍니다. "원문 보기"를 펼치면 Markdown 원문이 나옵니다. 설계 상태 반영안(반영하기·건너뛰기)도 결과 탭 맨 위에 나옵니다.
- 결과 탭 위의 "읽은 전문가"(config `inputs`)와 아래 "다음 전문가"(문서의 Handoff)는 그 전문가 페이지로 가는 링크입니다.
- 오른쪽 패널 맨 위의 "대지 사실"을 누르면 대지 페이지가 열립니다. 대지 사실은 한 전문가의 결과가 아니라 대지 분석가와 법규 검토자가 함께 읽는 프로젝트 자료라서 전문가 페이지와 따로 둡니다. 제도판이 보이는 동안 대지 페이지는 전문가 목록 자리에 넓게 열리고 제도판을 가리지 않습니다(제도판을 숨겼으면 전문가 페이지처럼 오른쪽 반쪽에 열림).
- 대지 분석가가 실행을 시작하면(설계자가 눌렀든 Conductor가 불렀든) 대지 페이지가 저절로 열립니다(2026-10-28 지훈 결정). 대지를 아직 저장하지 않았을 때 설계자가 대지 분석가의 "실행"을 누르면 바로 실행하지 않고 "찾기" 탭을 엽니다. 필지를 찾아 저장하면 그 대지로 대지 분석가가 실행되고, "대지 없이 브리프로 실행"을 누르면 브리프만으로 실행됩니다. Conductor가 대화에서 대지 분석가를 불렀을 때도 대지가 없으면 실행하지 않고 찾기 탭을 열며, Conductor가 넘긴 주소가 있으면 그 주소로 바로 검색해 둡니다(2026-10-29 지훈 결정). 대지가 저장돼 있으면 대지 페이지 맨 위에서 대지 분석가를 실행하거나 결과로 갈 수 있습니다.
- 대지를 저장하면 제도판의 대지 종이가 바로 새 필지 경계와 사실 줄로 다시 그려집니다. 대지 종이에는 정부 자료에서 규칙으로 만든 사실만 올라가고, 대지 분석가 결과(AI가 쓴 해석·미확인)는 다른 전문가처럼 AI 섹션에 놓입니다(2026-10-28 지훈 결정).
- 대지 페이지의 "찾기" 탭은 시·도 → 시·군·구 → 읍·면·동(→ 리)을 고르고 지번을 넣는 방식이 기본이고, "주소 붙여넣기"로 글자 검색도 합니다. 새 프로젝트를 만들 때 적은 대지 주소가 있으면 글자 검색 칸에 미리 들어갑니다. 찾은 필지를 여러 개 고르면(다른 지번을 찾아 더 고를 수도 있음) 하나의 대지로 조회해 저장합니다.
- "대지 사실" 탭은 저장된 값을 그대로 보여 줍니다(대지 개요, 용도지역과 법정 건폐율·용적률, 확인 필요, 지역·지구, 도시계획 도로, 필지, 기존 건축물, 건축제한 근거 조문, 미확인). 가져오지 못한 항목은 추정하지 않고 "미확인"으로 둡니다. 맨 아래에서 전문가가 받는 대지 사실 원문을 펼쳐 볼 수 있습니다.
- "조례" 탭은 대지의 도시계획 조례가 건폐율·용적률에 대해 말하는 조문을 하나도 거르지 않고 보여 줍니다. 맨 위 기본 수치는 조문 줄에서 정해진 규칙으로 읽은 값만 원문 줄·조문 번호와 함께 보여 주고, 읽지 못하면 "미확인"과 이유를 적습니다. 나머지 조문은 세 묶음(대지 위치로 정해지는 것, 설계로 얻을 수 있는 완화, 행정이 지정하는 것)으로 나오고, 조문마다 원문을 펼쳐 보고, 전문가에게 무엇이 가는지 보고, "숨기기"와 (완화·강화 묶음에서) "전문가가 원문 읽기"를 고릅니다. 이 선택은 프로젝트에 저장됩니다.
- "계획 용도" 탭은 지으려는 용도 이름의 일부로 토지이음 용도 이름을 찾고, 고른 이름이 대지의 용도지역·지구마다 지을 수 있는지(가능·금지 등 토지이음의 판단 그대로)와 단서 조항, 용도의 법적 정의를 보여 줍니다. 조회한 용도는 저장되고 ×로 지웁니다.
- 대지 분석가가 실행 중이면 대지 페이지 맨 위에 "실행 중"이 나오고, 끝나면 결과 보기와 다시 실행 버튼으로 바뀝니다. AI 섹션의 전문가 결과 종이는 한국어 전문가 이름("대지 분석가 결과")으로, 미리 보기는 Markdown 기호 없이 한국어 섹션 이름(\[사실\] 등)으로 보입니다.
- 대지 분석가와 법규 검토자 페이지의 결과 탭 위에는 어떤 대지로 실행되는지(조회 전이면 브리프만으로 실행된다는 안내)가 나옵니다.
- 정부 데이터 키가 없거나 거부되면(503) 오류 문구 옆에 설정 열기 버튼이 나옵니다.
- "찾기" 탭의 지도(`GET /api/site/map`)에는 저장한 대지(빨간 점선), 찾은 필지(얇은 선), 고른 필지(채움)가 그려집니다(경계는 `GET /api/site/shapes`). 지도를 누르면 그 자리의 필지(`GET /api/site/parcel-at`)가 고른 필지에 들어가고, 고른 필지를 다시 누르면 빠집니다. 줌 16보다 멀리서 누르면 확대하라는 안내만 나옵니다. 지적선은 브이월드가 줌 18부터 그려 줍니다. 지도 키가 없거나 거부되면 지도 대신 오류와 설정 버튼이 나옵니다.
- 체크리스트의 체크는 지금은 화면에만 남고 프로젝트에 저장되지 않습니다(새로고침하면 사라짐). 저장은 다음 작업입니다.
- 평가(도움 됨/아쉬움, 한 줄 의견)는 설정의 "사용 기록 보내기"가 켜져 있을 때만 전달됩니다(`docs/telemetry.md`).
- 프로젝트를 열면 제도판이 나옵니다. 창이 좁으면(900px 이하) 한 번에 한 패널만 보이고 아래 탭(제도판·전문가)으로 바꿉니다.
- 제도판 머리 아래 선택 막대에 고른 종이가 나옵니다. 이름을 누르면 상세 보기, "이 자료로 질문 →"은 명령창으로 커서를 옮기고, 매스안을 둘 이상 골랐으면 "두 안 비교 질문 →"이 비교 질문을 명령창에 채웁니다(보내기는 직접). 아무것도 안 골랐으면 "매스안 선택"으로 제도판의 매스안을 모두 고릅니다.
- 제도판은 3D 책상입니다. 대지 도면(필지 경계)이 가운데 있고, 대지 종이·매스안·메모·트레이싱지가 그 옆에 놓입니다. 마우스는 Rhino처럼 씁니다. 휠은 커서 기준 확대, 우클릭 끌기는 돌리고 기울이기(평면에서 끌면 바로 3D가 됨, 화면 가운데 한 점을 중심으로 돎), Shift+우클릭 끌기는 이동, Ctrl+우클릭 끌기는 확대입니다. 90° 가까이 눕히면(입면) 땅의 격자·그림자·대지선이 사라지고 건물과 지면선만 남습니다. 가운데 버튼 끌기도 이동, Alt+왼쪽 끌기는 돌리기(트랙패드용)입니다. 빈 곳 왼쪽 끌기는 Rhino처럼 선택 상자입니다. 왼쪽에서 오른쪽으로 끌면 상자 안에 다 들어온 종이만(실선), 오른쪽에서 왼쪽으로 끌면 상자에 걸친 종이까지(점선) 고르고, Shift를 누르면 더하고 Ctrl을 누르면 뺍니다. 3D에서는 종이의 이름표가 기준입니다. 빈 곳을 그냥 누르면 선택이 풀립니다. 대지 위 건물은 Rhino의 지오메트리처럼 동(블록) 하나하나를 고릅니다. 건물을 누르면 그 동만 노랗게 골라지고(Shift로 더하기·빼기, 선택 상자로 여러 동), 고른 동을 끌면 땅 위에서 옮겨집니다. 고른 동 위에는 Rhino 검볼처럼 빨간 u 화살표(대지 긴 변 방향), 초록 v 화살표, 파란 높이 화살표, 가운데 네모가 나타납니다. u·v 화살표는 그 방향으로만 옮기고, 화살표 위 작은 네모는 가로·세로 크기를 동 가운데를 기준으로 바꾸고(10cm 단위, 1m 이상), 파란 화살표는 층수를 바꿉니다(3D에서만 보임). Delete는 고른 동을 지웁니다(매스안에 한 동은 남김). 모두 Ctrl+Z로 되돌립니다. 이름표를 누르면 그 종이가 골라지고, 골라진 이름표를 끌면 종이를 옮깁니다. 보기는 Rhino의 Top·Perspective처럼 평면과 3D 둘이고, 3D 각도는 우클릭으로 정합니다. 한 글자 단축키는 없습니다(2026-11-02 지훈): 도구와 보기는 버튼이나 명령창의 명령 단어(plan, persp, zoom, select, note, pen, trace 등)로 켜고, 제도판에서 글자를 치면 그대로 명령창으로 갑니다. 제도판에서 쓰는 키는 Delete(지우기), Esc(선택 풀기), Ctrl+Z/Y, Ctrl+C/V, Ctrl+A뿐입니다. 동(블록)을 다루는 스케치업 기본 도구도 명령으로 켭니다(2026-11-02): rect·rec(사각형: 땅 위에서 끌어 새 동, 한 층 높이로 생기며 지금 매스안에 더해지고 없으면 새 매스안이 됨), pushpull·pp(밀고끌기: 윗면은 층수, 옆면은 그쪽 길이, 반대쪽 면은 그대로), move·m(이동, Ctrl을 누르고 시작하면 복사), copy·co(끌어서 복사), rotate·ro(회전: 가운데 기준, 5° 단위, Shift는 1°), scale·sc(크기: 가운데 기준, 위치와 가로·세로가 함께, 층수는 그대로), eraser(지우개: 누르거나 끌고 지나간 동), dist·di(줄자: 두 점 사이 거리). 제도판 위쪽 도구 막대의 아이콘 버튼도 같습니다(마우스를 올리면 이름·명령·쓰는 법). 보기 조절(평면/3D·기울기·방위·축척·확대·맞춤)은 오른쪽 아래 한 묶음이고, 조작 안내는 `help`에 있습니다. 오른쪽 패널은 라이노처럼 속성 | 레이어 | 전문가 탭입니다. 레이어는 라이노처럼 제도판과 함께 저장됩니다(`board.json`의 `layers`, `PUT .../board/layers`): 처음에는 종류마다 하나(대지·매스·트레이싱지·메모·사진·전문가 결과)이고, 레이어 칸의 도구로 새 레이어·하위 레이어·지우기(안의 것과 하위 레이어는 위 레이어로)·위아래 옮기기, 이름을 두 번 눌러 바꾸기, 현재(✓, 새로 만드는 종이가 들어감, 이번 방문에만)·보기·잠금·색(그 레이어의 동이 그 색)을 정합니다. 종이와 동을 다른 레이어로 옮기는 것은 속성의 "레이어" 값입니다(동은 자기 레이어가 없으면 매스안의 레이어). 숨기거나 잠근 레이어(하위 레이어도)는 제도판에서만 가려지거나 고를 수 없고, 전문가 검토에는 그대로 들어가며, 내보내기에서는 직접 만든 레이어가 그 이름("매스 - 타워")과 색의 CAD 레이어로 나갑니다. 주변 지형·건물은 화면에서만 숨기는 줄이 따로 있습니다. 그룹은 아무 종이·동이나 묶습니다(`group` 명령 또는 Ctrl+G, 풀기는 `ungroup`·Ctrl+Shift+G나 속성의 "그룹 풀기"): 하나를 누르면 함께 골라지고, 그룹 전체를 고르면 속성에 "그룹"으로 나옵니다. 같은 `group` 값을 가진 종이와 동이 한 그룹이며(`board-model.js`의 `groupChange`, `expandGroups`), 되돌리기로 풀거나 다시 묶습니다. 아무것도 안 고르면 레이어, 종이를 고르면 속성(매스안은 동 수·층고·최고 층수·건축면적·연면적, 대지 면적이 있으면 건폐율·용적률과 법정 상한)으로 바뀝니다. 속성 칸에서 값을 바로 고칩니다: 매스안·트레이싱지·사진의 이름, 매스안의 층고, 동 하나를 누르면 그 동의 층수·폭·깊이·각도(여러 동이면 층수를 한꺼번에). Enter나 칸을 떠나면 저장, Esc는 되돌리기, 범위를 벗어난 값은 저장하지 않고 이유를 칸 아래에 보여 주며, Ctrl+Z로 되돌립니다. 계산과 값 검사는 `board-model.js`의 `layerList`, `propertiesOf`, `propertyChange`. Ctrl+C/Ctrl+V는 고른 동을 복사해 5m 옆에 붙이고, Ctrl+A는 지금 매스안의 모든 동을 고릅니다. 동의 회전은 `a`(도, 반시계)로 저장되고 매스안 표의 회전 칸에서도 고칩니다.
- 종이를 누르면(끌지 않고) 그 종이만 골라지고 오른쪽에 상세 창이 열립니다. 상세 창이 열려도 제도판은 어두워지거나 막히지 않습니다(2026-11-07 지훈): 다른 종이를 누르면 그 종이로 바뀌고, 빈 제도판을 누르거나 ×·Esc로 닫습니다. 확대와 상관없이 읽는 크기로 보여 주고, 대지·매스안은 배치도(필지 경계와 동, 층수, 축척, 북쪽)를 함께 그립니다. 매스안은 "3D로 세우기"·"고치기", 메모는 그 자리에서 고쳐 쓰기, 모든 종이는 "제도판에서 크게 보기"와 "이 종이로 질문하기 →"가 있습니다. 종이 머리의 "상세 보기 ↗", 선택 막대와 입력칸 칩의 이름, 3D 이름표 카드의 "상세 보기"로도 열립니다. 메모는 누르면 상세 창 대신 그 자리에서 두 번 눌러 씁니다.
- 종이 모서리에 마우스를 대면 크기 조절 커서가 나오고, 끌면 반대쪽 모서리를 그대로 두고 크기가 바뀝니다(2026-11-07 지훈). 고른 종이와 마우스를 올린 종이는 네 모서리에 손잡이가 보입니다. 사진·PDF는 비율을 유지하고, 나머지는 자유롭게 바뀝니다(60~4000px, 6~400m). 트레이싱지는 대지 크기에 맞춰 덮여야 하므로 바뀌지 않습니다. Ctrl+Z로 되돌립니다.
- ↶·↷ 버튼과 Ctrl/⌘+Z, Ctrl/⌘+Shift+Z(또는 Ctrl+Y)로 되돌리고 다시 합니다. 옮기기, 크기 조절, PDF 페이지, 펜 획, 메모 글, 매스안 추가·고치기, 트레이싱지, 접기, 지우기가 대상이고 100단계까지, 새로고침하면 비워집니다. 저장은 그때그때 API로 되어 있어서 되돌리기도 반대 요청(PATCH·POST·DELETE)을 보냅니다. 지운 매스안·메모·트레이싱지·사진은 같은 id로 다시 놓이고, 전문가 결과 종이는 지우면 되돌릴 수 없습니다. AI 섹션에서 놓은 것은 되돌리기 대상이 아닙니다.
- 사진(2026-11-02): 도구 막대의 [사진 올리기], 명령 `photo`(`picture`, `image`), 사진 파일을 제도판에 끌어다 놓기, 스크린숏·복사한 그림 붙여넣기(Ctrl+V, 글 입력 칸 밖에서)로 대지 사진·손 스케치·참고 이미지를 종이로 올립니다. 한 번에 10장까지, 끌어다 놓으면 놓은 자리에, 나머지는 대지 오른쪽 빈자리에 놓입니다. 서버가 받는 PNG·JPEG·GIF·WebP 중 8MB 이하·긴 변 4096px 이하는 그대로 올리고, 그보다 크거나 다른 형식(Safari의 아이폰 HEIC 등 브라우저가 여는 것)은 화면이 긴 변 2560px JPEG로 줄여 올립니다. 브라우저가 열지 못하는 파일은 올리지 않고 이유를 알립니다. 종이는 사진 비율대로, 긴 변 300px(30m)로 놓이고, 사진을 누르면 상세 보기에서 크게 보고(원본은 새 탭), 이름을 붙이고, 제도판 위 크기(작게 200·보통 300·크게 500px)를 고릅니다. 지운 사진도 Ctrl+Z로 되돌립니다. AI에게는 사진 이름만 갑니다(그림은 보내지 않음).
- PDF(2026-11-07): 사진과 같은 방법([사진·PDF 올리기], 끌어다 놓기, 붙여넣기)으로 PDF를 올리면 그대로 서버에 저장되고, 첫 페이지 비율대로 긴 변 500px로 놓입니다. 화면은 pdf.js(`webui/app/vendor/pdfjs/`, `webui/app/pdf-view.js`)로 PDF를 보이는 크기에 맞춰 다시 그려서(확대가 멈추면 잠시 뒤), 종이를 키우거나 확대해도 선이 흐려지지 않습니다. 너무 크게 확대하면 캔버스 한도(긴 변 4096px)에서 멈춥니다. 상세 창에서 페이지를 넘기고(여러 쪽일 때), 누르면 원본 PDF를 새 탭에서 봅니다. 그림 파일(PNG·JPEG)은 원래 해상도보다 선명해지지 않으니, 도면은 PDF로 올리는 것이 좋습니다.
- 평면에서는 종이가 책상에 누워 있고, 기울이면(10° 넘게) 종이가 제자리에 선 이름표로 접혀서 매스와 대지만 크게 보입니다(2026-10-26 지훈 결정). 이름표를 누르면 옆에 내용 카드가 열리고(3D로 세우기, 고치기, 대화에 보내기, 평면에서 보기), Shift+누르기는 대화에 보낼 종이로 고릅니다. 대지 위에 덮인 트레이싱지는 이름표 없이 선이 땅에 그려집니다. 종이를 옮기거나 펜으로 그리는 것은 평면에서 합니다. 이름표끼리 가까우면 겹쳐 보일 수 있습니다.
- 매스안은 "＋ 매스안"이나 매스안 상세 창의 "고치기"로 숫자로 입력합니다(동마다 가로·세로·층수와 대지 중심에서의 u·v 위치). u는 가장 큰 필지의 가장 긴 변 방향입니다. 고른 매스안은 대지 위에 매스로 서고, 나머지 안은 "다른 안 겹쳐 보기"로 흐리게 볼 수 있습니다. 건폐율·용적률 같은 수치는 서버가 계산한 값만 보여 주고, 필지 면적을 모르면 "미확인"입니다.
- 밀고끌기와 크기 도구는 마우스를 누른 채 3px 이상 끌면 기존처럼 조절합니다. 동의 면을 이동 없이 클릭하면 수치 입력 창을 엽니다. 밀고끌기는 윗면의 목표 층수(1~200층), 옆면의 목표 가로·세로 길이(1~1000m)를 입력하고, 옆면은 반대쪽 면을 유지해 움직입니다. 크기는 선택한 동 전체의 배율(예: 1.2)을 입력하며, 기존 드래그처럼 가로·세로와 배치 간격만 바뀌고 층수는 유지합니다. 적용 전·취소·Esc는 저장하지 않습니다. 잘못된 값과 입력 중 다른 곳에서 바뀐 동은 덮어쓰지 않으며, 적용한 변경은 실행 취소 한 번으로 되돌립니다.
- AI가 만든 종이(Conductor의 매스안·메모, 전문가 결과)는 왼쪽 "AI 섹션"에 쌓입니다. 새 종이가 오면 AI 섹션이 열립니다. 카드마다 "3D 미리 보기", "제도판에 놓기", "대화에 보내기", "버리기"가 있습니다.
- 종이를 Shift+클릭(AI 섹션은 "대화에 보내기")으로 고르면 입력창 위 "함께 보낼 자료"에 칩이 생기고, 다음 메시지·전문가 실행·수정 요청에 함께 갑니다(8장까지). 칩의 ×로 빼고, 이름을 누르면 상세 창이 열립니다. 보낸 메시지 위에도 칩이 남습니다.
- 화면은 1초마다 다시 그려지지만 제도판은 그 밖(`#table-host`)에 있어서 3D 장면, 끌기, 입력 중인 메모가 끊기지 않습니다. 서버가 0, 0에 둔 새 종이는 화면이 대지 옆 빈자리에 놓고 그 위치를 저장합니다.
- 처음 실행(`config.local.yaml` 없음)이면 설정 창이 먼저 뜹니다. 저장을 누르면 다음부터는 뜨지 않습니다.
- 설정 창은 오른쪽에서 나오는 패널이고, AI 연결 → 정부 자료(Sida 키) → 작업 방식 → 개인정보 → 자료 출처(열린 프로젝트에서 켠 주변 3D의 색 범례와 지형·건물 자료 출처. 제도판 위에는 띄우지 않음) → 접힌 고급(실행 모드, API 키, 정부 키 직접 넣기) 순서입니다. 저장 버튼은 아래에 고정되고, 저장 안 한 변경이 있으면 그 옆에 알립니다(`model.js`의 `settingsChanges`, `settingsDirty`).
- 설정 창에서 Conductor를 "ChatGPT 구독"으로 고르면 로그인 버튼이 나옵니다. 새 창에서 로그인을 마치고 돌아오면 상태와 모델 목록이 바뀝니다.
