# 웹 화면 (webui/app)

`python webapp.py`(Windows는 `run.bat`)로 서버를 켜면 열리는 첫 화면(`http://127.0.0.1:8765/`)입니다. 팀원이 Figma 초안으로 만든 목업(PR #39)을 서버의 JSON API에 연결했습니다. 화면은 순수 HTML/CSS/JS이고 빌드 과정이 없습니다. 프로젝트와 대화는 브라우저가 아니라 이 PC의 `projects/` 폴더에 저장됩니다.

예전 서버 렌더링 화면(`/classic` 허브와 `/p/<프로젝트>` 페이지)은 2026-10-23에 없앴습니다. 서버가 템플릿(`webui/templates`, `webui/static`)으로 그리는 화면은 ChatGPT 로그인 결과 페이지 하나만 남았습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `webui/app/index.html` | 뼈대, 설정 창 |
| `webui/app/app.js` | 화면 그리기, API 호출, 작업 진행 따라가기 |
| `webui/app/model.js` | DOM과 `fetch`를 쓰지 않는 도우미 함수(검색·정렬, 대화 항목, 이벤트 알림 문구, Markdown, 저장할 정부 데이터 키, 화면 주소, 전문가별 결과 배치 `EXPERT_LAYOUTS`). `tests/webui/model.test.mjs`가 확인합니다 |
| `webui/app/table.js` | 제도판(`DraftingTable`): Three.js 장면, 종이, AI 섹션, 매스안 입력. 프로젝트를 열 때만 불러옵니다 |
| `webui/app/board-model.js` | 제도판의 DOM 없는 도우미(카메라·확대, 대지 범위, 동 꼭짓점, 새 종이 자리, 3D 이름표와 내용 카드 자리, 종이 이름, 매스안 입력 검사, 고른 종이). `tests/webui/board-model.test.mjs`가 확인합니다 |
| `webui/app/vendor/three.js` | three.js 0.186.1에서 제도판이 쓰는 부분만 묶은 파일(ESM). 고치지 말고 `scripts/three-vendor/README.md`대로 다시 만드세요 |
| `webui/app/site-map.js` | 대지 페이지 "찾기" 탭의 지도(`SiteMap`): 브이월드 배경·지적도, 찾은·고른·저장한 필지 경계, 클릭. 대지 페이지를 처음 열 때 불러옵니다 |
| `webui/app/vendor/leaflet.js`, `leaflet.css` | Leaflet 1.9.4(ESM으로 묶은 것, BSD-2 `LICENSE-leaflet.txt`). 고치지 말고 `scripts/leaflet-vendor/README.md`대로 다시 만드세요 |
| `webui/app/styles.css` | Figma v0.1 토큰과 화면 스타일 |

서버는 `/`에서 `index.html`을, `/app/...`에서 나머지 파일을 내보냅니다. 브라우저가 매번 새 파일인지 확인하므로(`Cache-Control: no-cache`) `git pull` 뒤 새로고침하면 바로 바뀝니다.

## 화면과 API

| 화면 | 쓰는 API |
|---|---|
| 프로젝트 목록 (`#/`) | `GET /api/projects`, 예시 프로젝트 `POST /api/projects/sample` |
| 새 프로젝트 (`#/new`) | `POST /api/projects` (`name`, `fields.type`·`site`·`intention`) |
| Conductor 대화 (`#/project/<이름>`) | `GET .../session`, 첫 인사 `POST .../session/opening`, 메시지 `POST .../session/messages`, 진행 `GET .../session/jobs/{id}` |
| 전문가 페이지 (`#/project/<이름>/expert/<id>` 결과, `.../chat/<채팅 id>` 분석 채팅, `.../versions/<버전 id>` 이전 버전) | 결과 문서 `GET .../modules/{agent}`, 이전 버전 `GET .../modules/{agent}/versions`, `.../versions/{id}`, 실행·수정 요청 `POST .../session/experts/{agent}/run`, 분석 채팅 목록과 새 채팅 `GET`/`POST .../experts/{agent}/chats`, 채팅 `GET .../experts/{agent}/chats/{chat_id}`, 메시지 `POST .../chats/{chat_id}/messages`, 평가 `POST .../experts/{agent}/feedback` |
| 대지 페이지 (`#/project/<이름>/site` 대지 사실, `.../site/ordinance` 조례, `.../site/uses` 계획 용도, `.../site/find` 찾기) | 대지 사실 `GET .../site`, 조례 `GET .../site/ordinance`와 조문 선택 `PUT .../site/ordinance/options/{id}`, 용도 이름 찾기 `GET /api/site/uses`, 계획 용도 조회·지우기 `POST`/`DELETE .../site/uses...`, 지역 목록 `GET /api/site/regions`, 지번으로 찾기 `GET /api/site/lots`, 주소로 찾기 `POST .../site/parcels`, 조회해 저장 `PUT .../site`, 지도 `GET /api/site/map`·`GET /api/site/parcel-at`·`GET /api/site/shapes`, 브리프의 대지 주소 `GET /api/projects/{name}` |
| 설계 상태 반영 승인 | `POST .../state-proposals/{id}/apply`, `.../skip` |
| 설정 창 | `GET`/`PUT /api/settings`, 키 `PUT /api/settings/keys/{openrouter·vworld·vworld_domain·data_go_kr·law}`, ChatGPT 로그인 `/api/settings/chatgpt...` |

| 제도판 | `GET .../board`(종이·AI 섹션·대지 도면·매스안 수치), 종이 `POST`/`PATCH`/`DELETE .../board/papers...`, AI 섹션 `POST .../board/tray/{id}/place`, `DELETE .../board/tray/{id}`. 자세한 것은 [board-api.md](board-api.md) |

API의 자세한 내용은 [session-api.md](session-api.md), [site-ordinance.md](site-ordinance.md), [state-editing.md](state-editing.md), [settings-api.md](settings-api.md), [chatgpt-login.md](chatgpt-login.md)에 있습니다.

## 동작

- Conductor 대화는 프로젝트마다 하나입니다. 대화가 비어 있으면 화면을 열 때 Conductor가 먼저 인사합니다.
- 메시지를 보내면 작업이 끝날 때까지 1초마다 진행을 받아 그립니다. 그동안 보내기 버튼은 꺼집니다(한 프로젝트에 작업 하나).
- Conductor나 설계자가 전문가를 실행하면 화면 오른쪽 아래 알림이 시작, 결과, 검토 필요를 알리고, 대화에 분석 카드가 남습니다. 카드나 전문가 패널을 누르면 그 전문가 화면이 열립니다.
- 오른쪽 전문가 패널에서 전문가를 펼치면 "결과 문서 보기", "＋ 새 분석 채팅", 분석 채팅 목록("분석 01 · 첫 질문")이 나옵니다. 펼친 상태는 화면을 다시 그려도 유지됩니다.
- 전문가를 열면 Conductor 대화는 왼쪽에 그대로 있고 오른쪽 반쪽이 그 전문가의 페이지가 됩니다. 가운데 줄을 끌어 너비를 바꿉니다.
- 전문가 페이지에는 탭 세 개(결과, 분석 채팅, 이전 버전)와 검토 영역(실행·다시 실행, 수정 요청, 평가)이 있습니다. 페이지가 넓으면 검토 영역이 오른쪽 열로, 좁으면 탭 아래 한 줄로 갑니다. 대지 분석가는 채팅 탭이 없고 수정 요청만 있습니다.
- 결과 탭은 전문가마다 다르게 배치합니다. 결과 문서의 `## 제목` 섹션을 잘라 카드, 표, 배지(확실/아마/확인, 브리프/후보/가정 등), 체크리스트, 순서 목록, 접는 문답으로 보여 줍니다. 배치는 `model.js`의 `EXPERT_LAYOUTS` 표 하나에 있어 그 표만 고치면 바뀝니다. 표에 없는 섹션은 끝에 그대로 붙고, 섹션을 하나도 못 찾으면 문서를 그대로 보여 줍니다. "원문 보기"를 펼치면 Markdown 원문이 나옵니다. 설계 상태 반영안(반영하기·건너뛰기)도 결과 탭 맨 위에 나옵니다.
- 결과 탭 위의 "읽은 전문가"(config `inputs`)와 아래 "다음 전문가"(문서의 Handoff)는 그 전문가 페이지로 가는 링크입니다.
- 오른쪽 패널 맨 위의 "대지 사실"을 누르면 대지 페이지가 열립니다. 대지 사실은 한 전문가의 결과가 아니라 대지 분석가와 법규 검토자가 함께 읽는 프로젝트 자료라서 전문가 페이지와 따로 둡니다. 제도판이 보이는 동안 대지 페이지는 전문가 목록 자리에 넓게 열리고 제도판을 가리지 않습니다(제도판을 숨겼으면 전문가 페이지처럼 오른쪽 반쪽에 열림).
- 대지 분석가가 실행을 시작하면(설계자가 눌렀든 Conductor가 불렀든) 대지 페이지가 저절로 열립니다(2026-10-28 지훈 결정). 대지를 아직 저장하지 않았을 때 설계자가 대지 분석가의 "실행"을 누르면 바로 실행하지 않고 "찾기" 탭을 엽니다. 필지를 찾아 저장하면 그 대지로 대지 분석가가 실행되고, "대지 없이 브리프로 실행"을 누르면 브리프만으로 실행됩니다. 대지가 저장돼 있으면 대지 페이지 맨 위에서 대지 분석가를 실행하거나 결과로 갈 수 있습니다.
- 대지를 저장하면 제도판의 대지 종이가 바로 새 필지 경계와 사실 줄로 다시 그려집니다. 대지 종이에는 정부 자료에서 규칙으로 만든 사실만 올라가고, 대지 분석가 결과(AI가 쓴 해석·미확인)는 다른 전문가처럼 AI 섹션에 놓입니다(2026-10-28 지훈 결정).
- 대지 페이지의 "찾기" 탭은 시·도 → 시·군·구 → 읍·면·동(→ 리)을 고르고 지번을 넣는 방식이 기본이고, "주소 붙여넣기"로 글자 검색도 합니다. 새 프로젝트를 만들 때 적은 대지 주소가 있으면 글자 검색 칸에 미리 들어갑니다. 찾은 필지를 여러 개 고르면(다른 지번을 찾아 더 고를 수도 있음) 하나의 대지로 조회해 저장합니다.
- "대지 사실" 탭은 저장된 값을 그대로 보여 줍니다(대지 개요, 용도지역과 법정 건폐율·용적률, 확인 필요, 지역·지구, 도시계획 도로, 필지, 기존 건축물, 건축제한 근거 조문, 미확인). 가져오지 못한 항목은 추정하지 않고 "미확인"으로 둡니다. 맨 아래에서 전문가가 받는 대지 사실 원문을 펼쳐 볼 수 있습니다.
- "조례" 탭은 대지의 도시계획 조례가 건폐율·용적률에 대해 말하는 조문을 하나도 거르지 않고 보여 줍니다. 맨 위 기본 수치는 조문 줄에서 정해진 규칙으로 읽은 값만 원문 줄·조문 번호와 함께 보여 주고, 읽지 못하면 "미확인"과 이유를 적습니다. 나머지 조문은 세 묶음(대지 위치로 정해지는 것, 설계로 얻을 수 있는 완화, 행정이 지정하는 것)으로 나오고, 조문마다 원문을 펼쳐 보고, 전문가에게 무엇이 가는지 보고, "숨기기"와 (완화·강화 묶음에서) "전문가가 원문 읽기"를 고릅니다. 이 선택은 프로젝트에 저장됩니다.
- "계획 용도" 탭은 지으려는 용도 이름의 일부로 토지이음 용도 이름을 찾고, 고른 이름이 대지의 용도지역·지구마다 지을 수 있는지(가능·금지 등 토지이음의 판단 그대로)와 단서 조항, 용도의 법적 정의를 보여 줍니다. 조회한 용도는 저장되고 ×로 지웁니다.
- 대지 분석가가 실행 중이면 대지 페이지 맨 위에 "실행 중"이 나오고, 끝나면 결과 보기와 다시 실행 버튼으로 바뀝니다. AI 섹션의 전문가 결과 종이는 한국어 전문가 이름("대지 분석가 결과")으로, 미리 보기는 Markdown 기호 없이 한국어 섹션 이름(\[사실\] 등)으로 보입니다.
- 대지 분석가와 법규 검토자 페이지의 결과 탭 위에는 어떤 대지로 실행되는지(조회 전이면 브리프만으로 실행된다는 안내)가 나옵니다.
- 정부 데이터 키가 없거나 거부되면(503) 오류 문구 옆에 설정 열기 버튼이 나옵니다.
- "찾기" 탭의 지도(`GET /api/site/map`)에는 저장한 대지(빨간 점선), 찾은 필지(얇은 선), 고른 필지(채움)가 그려집니다(경계는 `GET /api/site/shapes`). 지도를 누르면 그 자리의 필지(`GET /api/site/parcel-at`)가 고른 필지에 들어가고, 고른 필지를 다시 누르면 빠집니다. 줌 16보다 멀리서 누르면 확대하라는 안내만 나옵니다. 지적선은 브이월드가 줌 18부터 그려 줍니다. 지도 키가 없거나 거부되면 지도 대신 오류와 설정 버튼이 나옵니다.
- 체크리스트의 체크는 지금은 화면에만 남고 프로젝트에 저장되지 않습니다(새로고침하면 사라짐). 저장은 다음 작업입니다.
- 평가(도움 됨/아쉬움, 한 줄 의견)는 설정의 "사용 기록 보내기"가 켜져 있을 때만 전달됩니다(`docs/telemetry.md`).
- 프로젝트를 열면 Conductor 대화 오른쪽에 제도판이 나옵니다. 대화 위 "제도판" 버튼으로 숨기거나 다시 열고, 가운데 줄을 끌어 대화 너비를 바꿉니다. 창이 좁으면(900px 이하) 제도판은 숨겨집니다.
- 제도판은 3D 책상입니다. 대지 도면(필지 경계)이 가운데 있고, 대지 종이·매스안·메모·트레이싱지가 그 옆에 놓입니다. 끌어서 책상을 옮기고, Ctrl+휠로 확대하고, 우클릭(또는 Alt)+끌기로 돌리고 기울입니다. 1 평면, 2 액소, 3 투시, 0 전체 보기, V 선택, N 메모, P 펜, T 트레이싱지, Delete 지우기.
- 평면에서는 종이가 책상에 누워 있고, 기울이면(10° 넘게) 종이가 제자리에 선 이름표로 접혀서 매스와 대지만 크게 보입니다(2026-10-26 지훈 결정). 이름표를 누르면 옆에 내용 카드가 열리고(3D로 세우기, 고치기, 대화에 보내기, 평면에서 보기), Shift+누르기는 대화에 보낼 종이로 고릅니다. 대지 위에 덮인 트레이싱지는 이름표 없이 선이 땅에 그려집니다. 종이를 옮기거나 펜으로 그리는 것은 평면에서 합니다. 이름표끼리 가까우면 겹쳐 보일 수 있습니다.
- 매스안은 "＋ 매스안"이나 매스안 종이를 두 번 눌러 숫자로 입력합니다(동마다 가로·세로·층수와 대지 중심에서의 u·v 위치). u는 가장 큰 필지의 가장 긴 변 방향입니다. 고른 매스안은 대지 위에 매스로 서고, 나머지 안은 "다른 안 겹쳐 보기"로 흐리게 볼 수 있습니다. 건폐율·용적률 같은 수치는 서버가 계산한 값만 보여 주고, 필지 면적을 모르면 "미확인"입니다.
- AI가 만든 종이(Conductor의 매스안·메모, 전문가 결과)는 왼쪽 "AI 섹션"에 쌓입니다. 새 종이가 오면 AI 섹션이 열립니다. 카드마다 "3D 미리 보기", "제도판에 놓기", "대화에 보내기", "버리기"가 있습니다.
- 종이를 Shift+클릭(AI 섹션은 "대화에 보내기")으로 고르면 입력창 위에 칩이 생기고, 다음 메시지·전문가 실행·수정 요청에 함께 갑니다(8장까지). 보낸 메시지 위에도 칩이 남습니다.
- 화면은 1초마다 다시 그려지지만 제도판은 그 밖(`#table-host`)에 있어서 3D 장면, 끌기, 입력 중인 메모가 끊기지 않습니다. 서버가 0, 0에 둔 새 종이는 화면이 대지 옆 빈자리에 놓고 그 위치를 저장합니다.
- 처음 실행(`config.local.yaml` 없음)이면 설정 창이 먼저 뜹니다. 저장을 누르면 다음부터는 뜨지 않습니다.
- 설정 창에서 Conductor를 "ChatGPT 구독"으로 고르면 로그인 버튼이 나옵니다. 새 창에서 로그인을 마치고 돌아오면 상태와 모델 목록이 바뀝니다.
