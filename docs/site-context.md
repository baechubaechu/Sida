# 대지 주변 3D (지형·주변 건물·필지)

제도판의 "주변 3D" 버튼과 캐드·라이노 내보내기의 `대지 주변` 레이어가 쓰는 자료입니다. 대지 주변 200m의 지형, 지면 종류(대지·도로·인도·수계), 등고선, 주변 건물, 필지를 제도판 좌표로 만듭니다. 제도판 좌표는 0, 0이 대지 가운데이고 x는 동쪽, y는 북쪽, 단위는 m입니다. z는 대지 가운데 지반이 0입니다. 로직은 `sida/experts/site/context3d.py`, 지도 묶음은 `sida/experts/site/terrain_pack.py`, 경로는 `sida/experts/site/api.py`에 있습니다. 화면은 `webui/app/table.js`입니다.

공공 자료로 만든 참고용 모형이며 측량 결과가 아닙니다. 화면과 응답에 이 면책 문구(`site_context_disclaimer`)와 각 자료의 출처·기준일이 함께 나갑니다.

## API

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `GET /api/projects/{name}/site/context?size=medium&shape=square` | `size`: `small`(반경 100m)·`medium`(200m)·`large`(300m), `shape`: `square`(±반경 정사각형)·`circle`(반경 원)·`rect`(직사각형: 긴 변 2×반경, 짧은 변은 그 2/3, 600×900 우드락 비율), `orient`(직사각형만): `landscape`(긴 변 동서, 기본)·`portrait`(긴 변 남북). 안 주면 프로젝트에 저장한 범위(없으면 `medium`·`square`). 예전 `radius`(m, 50~500)도 `size` 대신 받음 | 아래 표. 대지 사실이 없으면 `404`, 범위·모양·반경이 잘못됐거나 대지 경계가 없으면 `400`, 브이월드 오류는 대지 API와 같은 코드(`503` 키, `429` 한도, `502` 연결) |
| `GET /api/projects/{name}/site/context/range` | | `{size, shape, orient, radius}`: 이 프로젝트에 저장한 범위(없으면 기본값) |
| `PUT /api/projects/{name}/site/context/range` | `{size, shape, orient?}` | `{size, shape, orient, radius}`. 프로젝트 폴더의 `site_context.json`에 저장(제도판 `board.json`이 아님). 모르는 값은 `400`, 없는 프로젝트는 `404`. 내보내기(`대지 주변` 레이어, 매스 높이)도 이 범위로 만듦 |

| 키 | 내용 |
|---|---|
| `origin`, `radius`, `size`, `shape`, `orient` | 원점(위경도), 반경(m), 범위 이름(반경이 그 값일 때, 아니면 `null`), 모양, 직사각형의 방향(다른 모양은 `landscape`) |
| `ground_elev` | 대지 가운데 지반의 해발 높이(m). 지형 묶음이 없으면 `null` |
| `terrain` | `{min, step, n, z, classes}`: `step`(4m) 간격 n×n 격자의 높이(남쪽 줄부터, 대지 가운데 기준)와 점마다 지면 종류 한 글자(`g` 대지, `r` 도로, `s` 인도, `w` 수계, `x` 원·직사각형 밖: 높이는 남기고 화면은 그 칸을 그리지 않음). 지형 묶음이 없으면 `null`(평지로 그림) |
| `contours` | 원본 등고선(5m 간격) `{elev, z, index, points}`. `index`는 25m마다의 계곡선 |
| `buildings` | `{outline(반시계), base(기초 바닥), ground(외곽선 아래 지반의 중앙값), foundation, top, height(지반에서), height_source, floors, use, name, on_site, ground_line(지형을 따라가는 접지선 [x,y,z])}` |
| `unknown_buildings` | 높이도 층수도 없는 건물: `{outline, base, ground_line, name}`. 상자로 세우지 않고 바닥선만 |
| `left_out` | 더 큰 건물 외곽선 안에 중심이 있는 작은 기록(겹친 기록) |
| `parcels` | 필지 `{ring, road, label}`. `road`는 지목 '도' |
| `areas` | 지형 묶음의 지면 영역 `{kind, ring}`(`road`·`sidewalk`·`water`) |
| `road_marks` | 정밀도로지도의 차선·노면표시를 지형 위(+0.03m)에 놓은 것. `{lines: [{color, width, pieces}], marks: [{kind, name, shapes, outline}]}`. `color`는 `yellow`·`white`·`blue`, `width`는 m(차선 0.15, 정지선 0.45), `pieces`는 칠한 조각마다 `[x,y,z]` 점(점선은 3m 칠·5m 빈칸으로 나눔). `shapes`는 채워 그릴 볼록 다각형(화살표·횡단보도 줄무늬), `outline`은 방향을 모르거나 그리지 않는 표시의 테두리. 묶음에 없으면 `null` (아래 "차선·노면표시") |
| `trees` | 규칙으로 놓은 가로수(표현용, 실제 나무 위치 아님) `{rule, height, crown, points: [[x,y,z]]}`. 인도가 없으면 `null` (아래 "가로수(표현용)") |
| `counts`, `notes` | 높이 원천별 건물 수, 일부 조회가 실패한 이유(`ledger:no_key` 등) |
| `terrain_sources`, `building_source`, `disclaimer` | 출처 이름과 기준일, 면책 문구 |

원·직사각형 범위에서는 건물·필지·지면 영역을 가운데가 범위 안에 있는 것만 남기고, 등고선도 범위로 자릅니다. 내보내기의 지형은 원이면 원 안 칸만 담은 메시(3dm, DXF), 직사각형이면 직사각형으로 자른 격자입니다. 같은 대지·반경·모양은 10분 동안 서버 메모리에서 다시 씁니다. 브이월드 응답은 저장하지 않습니다(이용약관 제19조⑥).

## 높이를 정하는 순서

1. 건축물대장 표제부 높이(`ledger`): 필지(PNU)별 조회(`datago.buildings`). 필지마다 대장의 동과 외곽선을 한 쌍씩 짝짓습니다(`assign_ledger`). 큰 동부터 건축면적에 가장 가까운 외곽선을 고르고, 면적 차이는 ±30%까지 봅니다. 외곽선에 그 동의 이름이 있거나 필지에 동 하나·외곽선 하나뿐이면 0.5~2배까지 봅니다. 짝이 없는 외곽선에는 대장 값을 붙이지 않습니다.
   - 건물 파일에 맞는 외곽선이 없는 동은 같은 필지의 1:5,000 수치지형도 건물 외곽선을 씁니다(파일로 내보냄). 그것도 없으면 브이월드 도로명주소 건물·건축물정보 외곽선을 쓰되 화면에만 그립니다(`display_only`, 내보내지 않음).
   - 이렇게 찾은 외곽선 안에 절반 넘게 들어가는 파일 외곽선은 그 건물의 조각으로 보고 뺍니다(`left_out`). 짝이 없는 파일 외곽선이 다른 외곽선에 놓인 동과 이름이 같으면 같은 건물의 중복 기록으로 보고, 그 기록의 높이·층수를 다시 쓰지 않습니다.
   - 응답의 건물마다 `match`(`source`: 외곽선 출처 `file`·`map`·`vworld`, `dong`, `ratio`: 외곽선 면적 ÷ 건축면적)가 있습니다. 제도판에서 주변 건물을 누르면 이 내용이 나옵니다.
2. 건물 자료의 높이(`file`: GIS건물통합정보 파일, `vworld`: 묶음이 없을 때 브이월드 건축물정보)
3. 층수 × 용도별 층고(`estimate`): 건축물대장 또는 건물 자료의 지상층수. 층고는 주거 2.9m, 업무·상업 3.8m, 그 밖 3.3m
4. 브이월드 API 층수 × 층고(`api_estimate`): 파일 건물에 높이·층수가 다 없을 때만, 도로명주소 건물(`gro_flo_co`)·건축물정보(`grnd_flr`)를 레이어마다 범위 질의 한 번으로 물어봅니다. 메모리에만 둡니다.
5. 1:5,000 수치지형도 건물 층수 × 층고(`map_estimate`): 같은 자리(중심이 안에 있거나 외곽선 절반 넘게 겹침)일 때만
6. 그래도 없으면 바닥선만(`unknown_buildings`)

3~5번은 추정이라 화면에서 다른 색으로, 안내에 "추정"으로 표시합니다. 비탈에서는 외곽선 아래 지반의 중앙 높이에 건물을 세우고, 기초를 가장 낮은 지반까지 내려 뜨는 쪽이 없게 합니다.

## Conductor와 전문가에게 가는 대지 요약 (2026-11-09)

Conductor는 메시지마다 대지 요약을 받습니다(`sida/experts/site/massing_brief.py`, 훅 `conductor_site`, `board.site_brief`). 세 부분입니다.

1. 대지 사실(면적, 용도지역, 법정·조례 건폐율·용적률 등, 긴 조문 목록은 뺌)
2. 필지 외곽선을 매스 동이 서는 제도판 좌표(u: 가장 큰 필지의 긴 변 방향, v: 그 직각, 대지 가운데에서 m)로, 범위와 긴 변·짧은 변 길이, u·v가 가리키는 방위
3. 주변 3D를 켜 둔 프로젝트면 짧은 요약: 대지 경계에서 60m 안의 건물을 북·동·남·서로 나눠 가장 가까운 것과 가장 높은 것(높이·층수·거리·이름), 대지 위 기존 건물, 도로가 붙은 쪽(지도 묶음의 도로 면), 대지의 경사

메시지는 주변 3D를 기다리지 않습니다. 화면(또는 내보내기)이 10분 안에 만든 것을 쓰고, 없으면 뒤에서 만들어 다음 메시지부터 넣습니다. 브이월드에서만 온 외곽선·층수 추정은 화면 전용이라 요약에서 뺍니다. 대지 사실을 받는 전문가(대지 분석가 등)에게도 3번 요약이 같이 갑니다. Conductor의 매스 제안 도구는 이 외곽선 안에 동을 놓으라고 안내합니다.

## 브이월드 3D 지도로 보기

주변을 실제 모양(굽은 지붕, 랜드마크)으로 보려면 제도판 머리의 "브이월드 3D"를 누릅니다. 브이월드의 3D 건물 모델은 약관(제14조: 3차원 공간정보는 공개제한 자료, 제19조: 저장·변경 금지) 때문에 시다로 가져올 수 없어서, 브이월드 공식 WebGL 3D 지도 API를 그대로 띄우고 그 위에 매스안을 얹습니다. 보는 용도이고, 내보내기는 이 문서의 지도 묶음으로 만든 `대지 주변` 레이어 그대로입니다. 자세한 동작과 숨긴 건물 저장은 [board-api.md](board-api.md) "브이월드 3D".

## 지도 묶음 만들기

원본과 묶음은 저장소 밖에 둡니다. 묶음 위치는 `~/Sida/context_data/*.terrain.sqlite`(`terrain_pack.TERRAIN_DIR`)입니다. 브이월드 '공간정보 다운로드'에서 로그인해 받은 파일(CC BY)로 만듭니다. 주변을 그릴 때는 이 폴더의 묶음 가운데 대지를 덮는 것을 모두 읽습니다.

```bash
pip install -e ".[pack]"   # pyshp, pyproj (묶음을 만들 때만)
python scripts/build_terrain_pack.py --name seoul --box 126.76,37.41,127.19,37.72 --contours <등고선·표고점 SHP 폴더> --source-date 2026-10-01
python scripts/build_terrain_pack.py --name seoul-junggu --box 126.94,37.53,127.04,37.59 --areas <1:5,000 도엽 SHP 폴더> --source-date 2026-01-27
python scripts/build_terrain_pack.py --name seoul --box 126.76,37.41,127.19,37.72 --buildings <AL_D010 zip 또는 그 폴더>
python scripts/build_terrain_pack.py --name seoul-junggu --box 126.76,37.41,127.19,37.72 --hdmap "<(B110)정밀도로지도_서울특별시_중구.zip>"
```

| 종류 | 원본 (브이월드 다운로드) | 묶음에 남는 것 |
|---|---|---|
| `--contours` | 연속수치지형도 등고선 `N3L_F0010000_*.shp`(시도별 파일 목록 xlsx로 번호 확인), 표고점 `N3P_F0020000.shp` | 등고선(해발 m), 표고점 |
| `--areas` | 수치지형도 v2.0 1:5,000 SHP(시군구 zip 안의 도엽 zip을 풀어 둔 폴더), 또는 같은 레이어의 연속수치지형도(시도 하나를 번호로 나눈 `N3A_E0032111_11.shp` 등) | 도로경계·보도·하천경계·실폭하천·호소 면, 건물 층수·용도 |
| `--buildings` | GIS건물통합정보 `AL_D010_<시도>_<날짜>.zip`(폴더를 주면 이름의 날짜가 가장 늦은 것) | 외곽선, PNU, 용도, 높이, 지상층수, 건물명, 동명, 데이터기준일자 |
| `--hdmap` | 국토지리정보원 정밀도로지도 벡터(국토정보플랫폼, 공공누리 1유형) `(B110)정밀도로지도_….zip`을 받은 그대로(또는 그 폴더). `HDMap_UTMK_정표고` 레이어만 읽고 측량 차량 기록·사진은 건너뜀 | 도로면 높이 점(1m에 하나): 일반도로(`RoadType` 1)의 주행경로링크 A2, 노면선표시 B2, 노면표시 B3, 보도 A4(`SubType` 3). 교량·터널·지하차도·고가차도(A3 차도구간이나 A2 링크의 `RoadType`가 1이 아닌 곳, 링크에서 2m 안)는 뺌. 보도 면은 `sidewalk` 영역으로도. 차선 B2(`Type`·`Kind`·선, 교량에서 끊음)와 노면표시 B3(`Type`·`Kind`·덮는 사각형·연결 링크 방향으로 1m 앞 점, 교량 위는 뺌)도 그리기용으로 |

- 정밀도로지도는 평면·수직 ±0.25m(1:5,000 수치지형도는 수직 ±1.67m)라, 도로면 높이 점이 있는 곳에서는 지형이 그 점을 따릅니다. 그 점에서 8m(`ROAD_TRUST`) 안의 등고선·표고점은 쓰지 않고, 이때 내보내는 등고선은 만든 지형에서 5m 간격으로 다시 그립니다. 범위는 큰 도로 위주라 이름 없는 골목은 등고선으로 메웁니다. 구 단위 zip이 수 GB인 것은 대부분 측량 차량 기록이라, 묶음은 작습니다(중구 26MB: 도로점 28만, 보도 669).
- 시험에 쓴 서울 묶음: 등고선 436MB(110,582선·99,191점), 중구 영역 35MB, 서울 건물 260MB(695,770동, 기준일 2026-03-06)
- 국토지리정보원 보안관리규정은 1:5,000 이상 지도의 좌표와 등고선·표고값을 인터넷으로 표시하지 못하게 합니다. 그래서 묶음은 각 PC 안에서만 쓰고, 외부 서버에 올리지 않습니다. 측량성과의 국외 반출도 금지라, 해외 서버(팀 VPS 포함)에는 두지 않습니다.

## 차선·노면표시

묶음(`--hdmap`)에 정밀도로지도의 차선(B2 노면선표시)과 노면표시(B3)가 있으면 주변 3D가 지형 위에 그립니다. 그리는 규칙은 `sida/experts/site/road_marks.py`에 있습니다.

- 차선 `Type` 세 자리: 색(1 황색, 2 백색, 3 청색), 단선(1)·겹선(2), 실선(1)·점선(2)·겹선의 왼쪽 점선(3)·오른쪽 점선(4). 점선은 도시부 차선처럼 3m 칠하고 5m 띄웁니다. `Kind` 530(정지선)만 0.45m, 나머지는 0.15m 폭입니다.
- 노면표시는 파일에 모양이 없고 덮는 사각형만 있습니다. 화살표(`Type` 1, `Kind` 5371 직진·5372 좌회전·5373 우회전·5381 직진·좌회전·5382 직진·우회전·5391 좌회전·우회전, 도로교통법 시행규칙 별표 6 번호)는 그 사각형 안에 화살표를 그리고, 표시가 가리키는 주행경로링크(A2)의 진행 방향으로 향하게 합니다. 링크가 없으면 방향을 지어내지 않고 사각형 테두리만 그립니다.
- 횡단보도(`Kind` 5321)는 차가 다니는 방향으로 놓인 0.45m 줄무늬로 그립니다. 그 밖의 표시는 사각형 테두리입니다.
- 같은 정밀도로지도 ID는 묶음이 둘(구 단위와 시범운행지구)이어도 한 번만 그립니다.
- 제도판 레이어 패널의 `주변 지형·건물` 아래 `차선`, `노면표시`로 끄고 켭니다. 계단식 보기에서는 그리지 않습니다.

## 가로수(표현용)

가로수 위치를 담은 자료 가운데 쓸 수 있는 것이 없어서(서울시 가로수 위치정보는 공공누리 제4유형: 상업적 이용·변경 금지), 묶음의 인도 면을 따라 규칙으로 세웁니다. 규칙은 `sida/experts/site/street_trees.py`에 있습니다.

- 인도 가장자리에서 1.2m 안쪽, 도로 면이 2m(1.2m + 틈 0.8m) 안에 있는 쪽 가장자리를 따라 8m 간격
- 건물 외곽선에서 2m, 물 위, 20m²보다 작은 인도 조각에는 세우지 않고, 두 나무가 6m보다 가깝지 않게
- 높이 8m, 수관 지름 5.2m, 만든 지형 위에 섬
- 화면 범례·자료 출처와 내보내기 레이어 이름에 "표현용"을 붙입니다. 레이어 패널 `주변 지형·건물` 아래 `가로수(표현용)`으로 끄고 켜고, 계단식 보기에서는 그리지 않습니다.

## 서울 전체의 물·도로·인도

물(수계)·도로·인도 면은 `--areas` 묶음에서만 옵니다. 중구 도엽으로만 묶음을 만들었다면 그 밖에서는 물과 인도가 빠지고 가로수도 서지 않습니다. 서울 전체는 브이월드 '공간정보 다운로드'의 연속수치지형도(서울)에서 도로경계 `N3A_A0010000`, 보도 `N3A_A0033320`, 하천경계 `N3A_E0010001`, 실폭하천 `N3A_E0032111`, 호소 `N3A_E0052114` 가운데 있는 것을 받아 한 폴더에 풀고 만듭니다(연속수치지형도에 없는 레이어는 서울 25개 구의 1:5,000 도엽으로 받습니다).

```bash
python scripts/build_terrain_pack.py --name seoul --box 126.76,37.41,127.19,37.72 --areas <연속수치지형도 SHP 폴더> --source-date <갱신일>
```

## 내보내기

`board_export_layers` 훅이 `대지 주변` 그룹 아래에 다음 레이어를 더합니다([board-api.md](board-api.md) "캐드·라이노로 내보내기").

- 지형: 3dm은 4m 격자를 제어점으로 한 NURBS 서피스, DXF는 MESH
- 지형 - 도로·인도·수계: 지형 위에 놓인 경계선
- 등고선, 등고선 - 계곡선
- 차선 - 황색·백색·청색: 칠한 조각마다 지형 위 폴리라인(가운데 선). 백색은 흰 도면에서 보이게 회색 레이어
- 가로수(표현용): 나무마다 지형 높이에 놓인 수관 원(지름 5.2m, 16각형)
- 노면표시: 화살표 조각·횡단보도 줄무늬·테두리를 닫힌 폴리라인으로
- 건물 - 측정 높이, 건물 - 추정 높이: 기초 바닥부터 지붕까지 솔리드
- 건물 - 높이 미확인(바닥선)

내보내기는 로컬 지도 묶음을 읽으며 브이월드 조회가 끊겨도 지형과 등고선을 내보냅니다. 건물은 묶음의 외곽선을 쓰고, 파일의 필지 번호로 조회 가능한 건축물대장 높이·층수를 보완합니다. 브이월드 전용 필지·건물·층수는 파일에서 제외합니다. 파일 건물의 높이나 층수가 끝까지 미확인이면 수치지형도 층수를 쓰거나 바닥선만 표시합니다. 화면에서 주변 3D를 켜면 설계 매스도 내보내기와 같이 바닥 윤곽 아래의 가장 낮은 지형 높이에 놓입니다.
